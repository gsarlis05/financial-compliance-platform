# Milestone 1 report: secure tenancy and core ledger

Status: **complete, awaiting product owner review** (PRs #9–#19, stacked; each is reviewable on
its own). No production or staging environment exists, and no migration has been applied
anywhere except local and CI databases (AC-G4).

## What you can do now
Sign in with mandatory two-factor authentication. Create business, personal or firm workspaces.
Invite people with roles. Set up a Cyprus business or personal chart of accounts and fiscal year.
Record journal entries through draft → submit → approve → post with segregation of duties. Correct
entries only by reversal. Close and lock periods, with two-person unlocks for exceptions. View the
trial balance (English or Greek) and export CSVs. Run integrity checks. Load the demo company with
`make demo` ([demo script](demo.md)); see the [user guide](user-guide/ledger.md).

| Module | Migrations | Content |
|---|---|---|
| identity | 0001 | users (UUIDv7, IdP subject) |
| tenancy | 0001–0003 | workspaces, legal entities, memberships, role assignments, invitations; RLS policies; `app_tenant_ids()` owned by the maintenance role |
| audit_log | 0001–0002 | hash-chained events and chain heads; append-only triggers |
| ledger | 0001–0008 | accounts, fiscal years, periods, settings, journals, entries, lines, sequences, posting counter, idempotency, balances, period unlocks, integrity runs; balance/immutability/period guard triggers; RLS on every table |

Database roles: `fcp_owner` (migrations), `fcp_app` (runtime, no BYPASSRLS, data privileges only),
`fcp_maintenance` (NOLOGIN, owns the cross-tenant ID function).

## Security controls (summary)
OIDC + PKCE in the backend-for-frontend pattern (no tokens in the browser); mandatory MFA by
`amr`; step-up for sensitive actions; `__Host-` cookies, CSRF, 30-minute idle and 12-hour absolute
timeouts. Deny-by-default permissions on every route; segregation of duties. PostgreSQL FORCE RLS
on every tenant table, composite tenant foreign keys, and a runtime role without BYPASSRLS.
Database triggers for balance, immutability and period locks. Append-only, hash-chained audit
trail. Log redaction by allow-list. problem+json errors without internals. Synthetic data only.

## Known limitations
- **No hosted environment.** Staging and production need your approval; the demo and all tests run
  locally and in CI. AC-G5's "on staging" is therefore met on the local stack.
- **No error tracker yet** (AC-E2 second half): unhandled errors return a scrubbed problem+json and
  are logged with redaction; wiring Sentry (or similar) waits for hosting.
- Single currency (EUR) for posting; multi-currency is out of scope for M1.
- No document attachments, bank import, VAT, tax, financial statements or AI (later milestones).
- The UI has no pagination for long entry lists, no general-ledger screen (API and CSV only), and no
  member-management screen (API only). Account deactivation is API-only.
- The nightly integrity job is a command (`make ops-checks`); scheduling it belongs to hosting.
- Demo data is monthly summaries with simplified VAT (see the [demo script](demo.md)).
- Custom roles and firm-to-client engagements (M5-4) are not implemented.
